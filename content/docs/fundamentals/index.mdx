## Mục tiêu học tập

Sau khi hoàn thành phần **Nền tảng**, bạn có thể:

- Giải thích observability khác monitoring như thế nào và chọn signal phù hợp cho một câu hỏi vận hành.
- Mô tả OpenTelemetry (OTel) là một framework trung lập với vendor để tạo, thu thập, xử lý và export telemetry.
- Đọc được đường đi của một record qua SDK, OTLP, Collector và backend.
- Hiểu vì sao một distributed trace vẫn là một trace duy nhất khi request đi qua nhiều service.
- Dùng semantic conventions để telemetry có thể truy vấn và so sánh nhất quán.

## Các khái niệm cần nắm

| Khái niệm | Câu hỏi nó trả lời |
| --- | --- |
| **Observability** | Từ các output bên ngoài, ta có thể suy luận hệ thống đang làm gì và vì sao lỗi xảy ra không? |
| **Telemetry** | Hệ thống đã phát ra dữ liệu gì về hoạt động của nó? |
| **Signal** | Dữ liệu thuộc loại trace, metric, log hay baggage? |
| **Instrumentation** | Code hoặc thư viện nào tạo ra telemetry? |
| **Context propagation** | Làm sao nối các operation ở những process khác nhau? |
| **Semantic convention** | Tên attribute và cấu trúc nào giúp dữ liệu có ý nghĩa nhất quán? |
| **Backend** | Nơi lưu trữ, truy vấn, trực quan hóa và cảnh báo trên telemetry. |
